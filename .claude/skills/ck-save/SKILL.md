# ck-save — 写交接检查点

## 原则

**只写 git 写不下的东西。** 改了哪些文件、改了什么内容，`git log` 和 `git diff` 已经记得比你准。
重复记录它们唯一的作用是制造一份会过期的副本，而**过期的检查点比没有检查点更糟** ——
它会让下一个会话自信地从错误的状态继续。

因此本检查点只记四类信息，全部是过程信息，git 里没有：

1. **手头那一步** —— 正在实现哪条 FR / 哪个文件，验收标准是什么
2. **试过并否决的方案** —— 以及否决的理由（最容易丢、重做代价最大的一类）
3. **卡住的决策** —— 指向 PRD §13 的 Q 编号或决策台账，不要在这里重述结论
4. **下一步的具体动作** —— 能直接粘进终端的命令，不是"继续开发权限模块"

## 步骤

### 1. 采集锚点（用于下次校验检查点是否仍然成立）

```bash
git rev-parse HEAD
git status --short
date -Iseconds
```

### 2. 采集客观状态 —— 跑，不要凭记忆写

```bash
pytest -m "not integration" -q 2>&1 | tail -5
```

记录实际输出的那一行结论（如 `26 passed` 或 `1 error`）。
**不得写"测试应该是绿的"** —— 没跑就写"未跑"。

### 2·5. 先判断该写进哪个文件

```
.kb/checkpoint.md   交接状态，每次 ck-save 【覆盖重写】
.kb/decisions.md    范围与架构决策，【只追加，永不删改历史条目】
```

**判断标准：这条信息过期之后，还需要被人看到吗？**

- 「手头在做 X，下一步跑 Y」—— 过期即无用 → checkpoint，覆盖掉正好
- 「B 档助手被否决，因为会把注入落点搬进产品内部」—— **理由不会过期**。
  丢了它，这个需求半年后会被原样重新提出、重新实现一遍 → decisions，追加

写错位置的后果是不对称的：决策写进 checkpoint 会被下一次 ck-save **静默删掉**，
而交接状态写进 decisions 只是让那个文件变脏。**拿不准就写 decisions。**

### 3. 覆盖写入 `.kb/checkpoint.md`

单一文件，直接覆盖，不要生成 `checkpoint-2.md` 之类的新文件。
历史由 git 保存：`git log -p .kb/checkpoint.md` 就是完整的交接历史。

模板：

```markdown
# 交接检查点 / Checkpoint

| | |
| --- | --- |
| 保存时间 | <date -Iseconds 的输出> |
| HEAD | <git rev-parse HEAD 的前 12 位> |
| 工作区 | 干净 / 有未提交改动（列出 git status --short） |
| 单元测试 | <实跑结果，如 26 passed / 1 error：kb.identity.permissions 缺失 / 未跑> |

## 1. 手头这一步

- **目标**：<哪条 FR 或哪个文件，一句话>
- **验收**：<可执行的判定，如 `make test-unit` → 26 passed>
- **进度**：<已完成什么 / 还差什么>

## 2. 试过并否决的

| 方案 | 为什么否决 |
| --- | --- |
| <方案> | <理由。写清楚，否则下个会话会重试同一条路> |

（没有就写"无"。不要为了填表编内容。）

## 3. 卡住的决策

| 编号 | 问题 | 在等谁 |
| --- | --- | --- |
| <Q-xx / A-xx> | <一句话> | <责任方> |

（只写编号和一句话；结论在 PRD §13 与决策台账里，这里重述必然会不一致。）

## 4. 下一步

```bash
<能直接粘进终端的命令>
```

<如果下一步需要先读某份文档的某几节，在这里点名：文件 + 节号>

## 5. 本次会话未解决的疑问

- <留给下个会话的具体问题，没有就删掉本节>
```

### 4. 提交

```bash
git add .kb/checkpoint.md
git commit -m "ck-save: <手头这一步的一句话>"
```

## 禁止

- **不要写进度百分比** —— 无法验证，且永远偏乐观
- **不要复述 PRD 或 AGENTS.md 的内容**。它们就在仓库里，重述只会产生第二份会漂移的真相
- **不要记"下次要注意 X"这类泛化叮嘱** —— 属于约定的，写进 `AGENTS.md`；属于一次性的，写进第 4 节
- **不要在工作区有未提交改动时假装干净**。如实列出，让下个会话自己判断要不要先 `git stash`
